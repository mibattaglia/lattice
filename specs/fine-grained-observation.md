# Fine-Grained Observation (Spec A): keyPath-addressed view-state observation

Status: ✅ Complete — depends on
[`observable-state-identity-preserving-merge.md`](./observable-state-identity-preserving-merge.md)
landing first. **Breaking change** (see "Behavior change" below); no opt-in surface.

## Problem

`ViewModel<F>` collapses all view-state observation onto one coarse key path, so **every reduce
invalidates every view that reads any view-state property.**

The collapse does **not** come from the read path. View-state properties generated by
`@ObservableState` are computed accessors whose getter calls
`registrar.access(self, keyPath: \.prop)` (see `ObservationStateTrackedMacro` in
[`ObservableStateMacro.swift`](../Sources/LatticeMacros/Plugins/Derived/ObservableStateMacro.swift)).
So both `viewModel.<member>` and `_ViewModelBinding`'s `viewState[keyPath:]` reads already register
on the view state's **own** nested registrars — `\.header`, `\.header.title`, etc. — in addition
to `\.viewState`.

The collapse comes from the **write path**: the `viewState` `_modify` accessor fires
`withMutation(of: self, keyPath: \.viewState)` unconditionally after every reduce
([`ViewModel.swift:187-190`](../Sources/Lattice/Presentation/ViewModel/ViewModel.swift)), and reduce
mutates `into: &viewState` (`:277`). Because every reader is also registered on `\.viewState`, that
one unconditional fire invalidates all of them, and the nested per-key-path registrars (and the
gating in `ObservationStateRegistrar.mutate`/`didModify`) are wasted.

## Goal

Let a view re-render only when the specific nested value it reads changes — without identity churn
and without detached value snapshots — by removing the coarse `\.viewState` fire so reduce
notifications flow through the view state's own registrar tree.

## Behavior change (breaking) — converge on TCA's observation model

Today `ViewModel` fires the coarse `\.viewState` on **every** reduce. TCA does **not**: its `Store`
fires the equivalent coarse `\.currentState` **only when the root state's `_$id` changes**, and lets
the per-property nested registrars drive everything else. See `Store.swift` (the `subscribeToDidSet`
pipeline):

```swift
core.didSet
  .compactMap { (self?.withState(\.self) as? T)?._$id }   // project to _$id
  .removeDuplicates()                                      // only when _$id actually changes
  .dropFirst()
  .sink { ... } receiveValue: { [weak self] _ in
      self?._$observationRegistrar.withMutation(of: self, keyPath: \.currentState) {}
  }
```

and the coarse read surface it pairs with (`Store+Observation.swift`):

```swift
var observableState: State {
    self._$observationRegistrar.access(self, keyPath: \.currentState)
    return self.currentState
}
public subscript<Value>(dynamicMember keyPath: KeyPath<State, Value>) -> Value {
    self.state[keyPath: keyPath]
}
```

This change makes Lattice's `viewState` fire its coarse `\.viewState` on the same condition —
only when `_viewState._$id` changes — so `viewModel.<member>` access and all `_ViewModelBinding`
getters become fine-grained by default. The current unconditional fire is the anomaly versus TCA;
this converges Lattice onto TCA's model rather than inventing a new one. Lattice has no
`core.didSet` publisher, so the gate is expressed inline in `_modify` (compare `_$id` across the
`yield`) — identical observable behavior, no reactive plumbing.

The one residual caveat (also true of TCA): a view that reads the **whole** `viewState` value
(e.g. `SomeView(state: viewModel.viewState)`) and not a property of it will only re-render when the
root `_$id` changes, not on an in-place leaf mutation. This matches SwiftUI `@Observable`
semantics — observe by reading the properties you depend on, not the container. Pass the
`viewModel` down and read leaf properties in the leaf view.

### Enum-root view state

`@ObservableState` enums carry **no registrar of their own** (`enumExpansion` emits only `_$id`
and `_$willModify`); their observation is mediated entirely by the containing registrar. When the
whole `ViewState` is an enum, that container is the view model's `_$observationRegistrar` via
`\.viewState`. So a view that switches over the enum:

```swift
VStack {
    switch viewModel.viewState {        // registers \.viewState only
    case let .content(content):
        ContentView(content)            // ContentView.body reads content.foo → payload registrar
    case .empty:
        EmptyView()
    }
}
```

relies on the coarse `\.viewState` fire to re-render the `switch` when the **case** changes
(`.content → .empty`). Because a case change changes the enum's `_$id` (different tag), the
`_$id`-gated fire triggers exactly there — matching TCA's `removeDuplicates()`-on-`_$id` behavior.
In-place mutations of a case's payload don't change the root `_$id`, so they don't fire coarse;
the child view re-renders via its own payload registrar. Deleting the fire outright would break
this case-switch re-render, which is why the gate (not removal) is required.

## Why this works (the invariant it stands on)

1. **The top-level `_viewState` registrar instance is stable for the view model's lifetime.**
   Reduce mutates `_viewState` in place through `_modify` (`:277`); it never reassigns
   `_viewState` to a fresh-identity value. So the registrar tree rooted at `_viewState` persists.
2. **Wholesale nested rebuilds preserve nested registrar instances.** Guaranteed by the
   identity-preserving merge: `viewState.section = rebuilt` routes through the
   `Value: ObservableState` `mutate` overload → `section._$merge(with:)`, keeping `section`'s
   registrar alive and notifying only changed leaves.

Therefore a reader registered on `_viewState`'s registrars sees every relevant change, never
observes a stale snapshot, and — with the coarse `_modify` fire now gated on a root `_$id` change —
is no longer invalidated by unrelated in-place reduces, while enum-root `switch` views still get
the coarse signal on a case change.

### Precision model (document this clearly)

- Reducer mutates **in place** (`viewState.section.title = x`): `didModify` finds the section
  identity unchanged and does **not** fire `\.section`; only `section`'s registrar fires
  `\.title`. A reader of `\.section.subtitle` is **not** invalidated. ✅ maximally fine-grained.
- Reducer **rebuilds a slice wholesale** (`viewState.section = Section(...)`, content changed):
  the merge overload fires `\.section` at the parent **and** merges leaves. A reader of
  `\.section.subtitle` **is** invalidated even if `subtitle` didn't change, because `\.section`
  fired. Still correct and leak-free. Prefer in-place mutation in reducers for maximum precision.

## Source changes

### `Sources/Lattice/Presentation/ViewModel/ViewModel.swift`

Gate the coarse fire in the `viewState` `_modify` accessor on a top-level `_$id` change, instead
of firing unconditionally. The nested `@ObservableState` registrars already fire the precise key
paths during the yielded mutation; the coarse `\.viewState` fire is now reserved for root
identity/case changes (the enum-switch case), matching TCA.

```diff
     public private(set) var viewState: ViewState {
         get {
             _$observationRegistrar.access(self, keyPath: \.viewState)
             return _viewState
         }
         set {
             if _viewState._$id == newValue._$id {
                 _viewState = newValue
             } else {
                 _$observationRegistrar.withMutation(of: self, keyPath: \.viewState) {
                     _viewState = newValue
                 }
             }
         }
         _modify {
-            defer {
-                _$observationRegistrar.withMutation(of: self, keyPath: \.viewState) {}
-            }
+            let oldID = _viewState._$id
             yield &_viewState
+            if _viewState._$id != oldID {
+                _$observationRegistrar.withMutation(of: self, keyPath: \.viewState) {}
+            }
         }
     }
```

That is the entire change.

- The `get`'s `access(self, keyPath: \.viewState)` and the `set`'s identity-swap fire are
  unchanged. The `_modify` now fires `\.viewState` only when the yielded mutation changed the
  root `_$id` — i.e. a top-level identity/case change — which is the only situation a reader of
  the whole value (or an enum-root `switch`) needs the coarse signal for. In-place struct
  mutations leave the root `_$id` stable, so they fire nothing coarse and are driven entirely by
  the nested registrars.
- This mirrors TCA's `Store` pipeline, which projects `didSet` to `_$id`, applies
  `removeDuplicates()`, and only then fires `withMutation(of: self, keyPath: \.currentState)`.
- No new API, no new file. `viewModel.<member>` and every `_ViewModelBinding` getter
  (`ViewModelBinding.swift`) become fine-grained automatically because they already read through
  the nested computed getters.

No macro changes, no action-loop changes.

## Usage

```swift
struct DashboardView: View {
    @State var viewModel: ViewModel<DashboardFeature>

    var body: some View {
        VStack {
            HeaderView(viewModel: viewModel)
            FooterView(viewModel: viewModel)
        }
    }
}

struct HeaderView: View {
    let viewModel: ViewModel<DashboardFeature>
    var body: some View {
        // Re-renders only when header.title changes — NOT when footer or any other slice changes.
        Text(viewModel.header.title)
    }
}
```

Bindings are likewise fine-grained:

```swift
TextField("Name", text: $viewModel.name.sending(\.nameChanged))  // re-renders only on `name`
```

## Tests

New file `Tests/LatticeTests/PresentationTests/FineGrainedObservationTests.swift`:

```swift
import Foundation
import Observation
import Testing

@testable import Lattice

@ObservableState private struct Section: Equatable, Sendable {
    var title: String
    var subtitle: String
}

@ObservableState private struct DashViewState: Equatable, Sendable, DefaultValueProvider {
    static let defaultValue = Self(header: Section(title: "h", subtitle: "s"), count: 0)
    var header: Section
    var count: Int
}

private struct DashDomain: Equatable, Sendable { var count = 0; var title = "h"; var subtitle = "s" }

@CasePathable private enum DashAction: Sendable {
    case bumpCount        // changes only `count`
    case setTitle(String) // changes only `header.title` (in place)
}

private struct DashInteractor: Interactor, Sendable {
    typealias DomainState = DashDomain
    typealias Action = DashAction
    var body: some InteractorOf<Self> { self }
    func interact(state: inout DashDomain, action: DashAction) -> Emission<DashAction> {
        switch action {
        case .bumpCount: state.count += 1
        case .setTitle(let t): state.title = t
        }
        return .none
    }
}

private struct DashReducer: ViewStateReducer, Sendable {
    typealias DomainState = DashDomain
    typealias ViewState = DashViewState
    var body: some ViewStateReducerOf<Self> { self }
    func initialViewState(for s: DashDomain) -> DashViewState { .defaultValue }
    func reduce(_ s: DashDomain, into v: inout DashViewState) {
        v.count = s.count
        v.header.title = s.title          // in-place
        v.header.subtitle = s.subtitle    // in-place
    }
}

@MainActor
@Suite struct FineGrainedObservationTests {
    private func makeViewModel()
        -> ViewModel<Feature<DashAction, DashDomain, DashViewState>>
    {
        ViewModel(
            initialDomainState: DashDomain(),
            feature: Feature(interactor: DashInteractor(), reducer: DashReducer())
        )
    }

    @Test func unrelatedChangeDoesNotInvalidate() {
        let vm = makeViewModel()
        var fired = false
        withObservationTracking { _ = vm.header.title } onChange: { fired = true }

        vm.sendViewEvent(.bumpCount)      // changes count, not header.title
        #expect(!fired)
    }

    @Test func relatedChangeInvalidates() {
        let vm = makeViewModel()
        var fired = false
        withObservationTracking { _ = vm.header.title } onChange: { fired = true }

        vm.sendViewEvent(.setTitle("new"))
        #expect(fired)
        #expect(vm.viewState.header.title == "new")
    }

    @Test func inPlaceSiblingMutationIsFineGrained() {
        let vm = makeViewModel()
        var subtitleFired = false
        withObservationTracking { _ = vm.header.subtitle } onChange: { subtitleFired = true }

        vm.sendViewEvent(.setTitle("new"))   // only title changes, in place
        #expect(!subtitleFired)
    }
}
```

Enum-root regression test (the case-switch scenario), same file:

```swift
// When the whole view state is the enum itself:
@ObservableState private enum RootPhaseViewState: Equatable, Sendable, DefaultValueProvider {
    static let defaultValue = Self.loading
    case loading
    case content(String)
}

private struct PhaseDomain: Equatable, Sendable { var loaded = false; var text = "" }

@CasePathable private enum PhaseAction: Sendable {
    case load(String)   // .loading -> .content (case change)
}

private struct PhaseInteractor: Interactor, Sendable {
    typealias DomainState = PhaseDomain
    typealias Action = PhaseAction
    var body: some InteractorOf<Self> { self }
    func interact(state: inout PhaseDomain, action: PhaseAction) -> Emission<PhaseAction> {
        switch action {
        case .load(let t): state.loaded = true; state.text = t
        }
        return .none
    }
}

private struct RootPhaseReducer: ViewStateReducer, Sendable {
    typealias DomainState = PhaseDomain
    typealias ViewState = RootPhaseViewState
    var body: some ViewStateReducerOf<Self> { self }
    func initialViewState(for s: PhaseDomain) -> RootPhaseViewState { .loading }
    func reduce(_ s: PhaseDomain, into v: inout RootPhaseViewState) {
        v = s.loaded ? .content(s.text) : .loading
    }
}

@MainActor
@Suite struct EnumRootObservationTests {
    private func makeViewModel()
        -> ViewModel<Feature<PhaseAction, PhaseDomain, RootPhaseViewState>>
    {
        ViewModel(
            initialDomainState: PhaseDomain(),
            feature: Feature(interactor: PhaseInteractor(), reducer: RootPhaseReducer())
        )
    }

    // A view that `switch`es over the enum registers only `\.viewState`; a case change must
    // re-render it. This is the regression that deleting the coarse fire would break.
    @Test func caseChangeInvalidatesWholeStateObserver() {
        let vm = makeViewModel()
        var fired = false
        withObservationTracking { _ = vm.viewState } onChange: { fired = true }

        vm.sendViewEvent(.load("hi"))   // .loading -> .content : root _$id changes
        #expect(fired)
        #expect(vm.viewState == .content("hi"))
    }
}
```

## Demo project

Add a new local example package `ExampleProject/FineGrainedExamplePackage` (mirroring the existing
`TodosExamplePackage`/`SearchExamplePackage` layout) and wire it into `ContentView.swift`'s
`Example` enum as a `case fineGrained`. The demo must make the re-render boundary *visible* so the
behavior change is observable in a running app, not just in tests.

Shape:

- A `FineGrainedFeature` with view state `{ header: { title }, footer: { count } }` and actions
  `setTitle(String)` / `bumpCount`, each mutating only its own slice **in place** in the reducer.
- A root view that composes two sibling subviews, `HeaderView` and `FooterView`, each given the
  same `ViewModel<FineGrainedFeature>`.
- Each subview holds a render counter so taps prove which subview re-rendered:

```swift
struct HeaderView: View {
    let viewModel: ViewModel<FineGrainedFeature>
    private final class Renders { var count = 0 }
    private let renders = Renders()
    var body: some View {
        renders.count += 1
        return VStack(alignment: .leading) {
            Text(viewModel.header.title)            // reads only header.title
            Text("HeaderView renders: \(renders.count)").font(.caption).foregroundStyle(.secondary)
        }
    }
}
```

`FooterView` is the symmetric twin reading `viewModel.footer.count`. Two buttons drive
`setTitle`/`bumpCount`.

Expected, demonstrable behavior with this change:

- Tapping **“Change title”** increments only `HeaderView renders:`; `FooterView renders:` stays put.
- Tapping **“Bump count”** increments only `FooterView renders:`; `HeaderView renders:` stays put.

Before this change (unconditional coarse fire) both counters would advance on every tap. Include a
third subview that switches over an enum slice to also show the enum-root case-change path
re-rendering its `switch` while siblings stay put.
