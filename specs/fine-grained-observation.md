# Fine-Grained Observation (Spec A): key-path-addressed state observation

Status: ✅ Complete — depends on
[`observable-state-identity-preserving-merge.md`](./observable-state-identity-preserving-merge.md)
landing first. **Breaking change** (see "Behavior change" below); no opt-in surface. Updated for
the [unified feature state](./plans/unified-feature-state.md): observation runs on the feature's
one `@FeatureState` state, read through its generated `ViewState` projection, and the coarse fire
is gated in the view model's commit step.

## Problem

Before this spec, `ViewModel<F>` collapsed all observation onto one coarse key path, so **every
action invalidated every view that read any state member.**

The collapse did **not** come from the read path. Members generated by the state macro are
computed accessors whose getter calls `registrar.access(self, keyPath: \.prop)` (see
`ObservationStateTrackedMacro` in
[`ObservationStateMacros.swift`](../Sources/LatticeMacros/Plugins/ObservationStateMacros.swift)). So
`viewModel.<member>` and `_ViewModelBinding` reads already registered on the state's **own**
nested registrars — `\.header`, `\.header.title`, etc. — in addition to the coarse key path.

The collapse came from the **write path**: the view model fired its coarse key path
unconditionally after every action. Because every reader was also registered on it, that one
unconditional fire invalidated all of them, and the nested per-key-path registrars (and the
gating in `ObservationStateRegistrar.mutate`/`didModify`) were wasted.

## Goal

Let a view re-render only when the specific nested value it reads changes — without identity
churn and without detached value snapshots — by firing the coarse key path only on a root
identity change, so notifications flow through the state's own registrar tree.

## Behavior change (breaking) — converge on TCA's observation model

TCA does not fire its coarse key path on every action: its `Store` fires the equivalent coarse
`\.currentState` **only when the root state's `_$id` changes**, and lets the per-property nested
registrars drive everything else. See `Store.swift` (the `subscribeToDidSet` pipeline):

```swift
core.didSet
  .compactMap { (self?.withState(\.self) as? T)?._$id }   // project to _$id
  .removeDuplicates()                                      // only when _$id actually changes
  .dropFirst()
  .sink { ... } receiveValue: { [weak self] _ in
      self?._$observationRegistrar.withMutation(of: self, keyPath: \.currentState) {}
  }
```

and the coarse read surface it pairs with (`Store+Observation.swift`):

```swift
var observableState: State {
    self._$observationRegistrar.access(self, keyPath: \.currentState)
    return self.currentState
}
public subscript<Value>(dynamicMember keyPath: KeyPath<State, Value>) -> Value {
    self.state[keyPath: keyPath]
}
```

Lattice's `ViewModel` fires its coarse `\.state` on the same condition — only when the root
state's `_$id` changes — so `viewModel.<member>` reads and all `_ViewModelBinding` getters are
fine-grained by default. This converges Lattice onto TCA's model rather than inventing a new
one. Lattice has no `core.didSet` publisher, so the gate is expressed inline in the commit step
(compare `_$id` across the transition) — identical observable behavior, no reactive plumbing.

The one residual caveat (also true of TCA): reading the whole `viewModel.viewState` value
registers only the root, so a body that reads no member of it re-renders only when the root
`_$id` changes, not on an in-place leaf mutation. A child view handed that value
(`SomeView(state: viewModel.viewState)`) holds a snapshot: its member reads are notified, because
the snapshot shares the live registrars, but they re-read the snapshot and show stale values.
This matches SwiftUI `@Observable` semantics — observe by reading the members you depend on, not
the container. Pass the `viewModel` (or a scope) down and read leaf members in the leaf view.

### Enum-root state

`@FeatureState` enums carry **no registrar of their own** (the enum expansion emits only `_$id`
and `_$willModify`); their observation is mediated entirely by the containing registrar. When the
whole state is an enum, that container is the view model's `_$observationRegistrar` via
`\.state`. So a view that switches over the enum:

```swift
VStack {
    switch viewModel.viewState {        // registers \.state only
    case let .content(content):
        Text(content.title)             // payload member read → payload registrar
    case .empty:
        EmptyView()
    }
}
```

relies on the coarse fire to re-render the `switch` when the **case** changes
(`.content → .empty`). Because a case change changes the enum's `_$id` (different tag), the
`_$id`-gated fire triggers exactly there — matching TCA's `removeDuplicates()`-on-`_$id` behavior.
In-place mutations of a `@FeatureState` payload don't change the root `_$id`, so they don't fire
coarse; the payload member reads re-render the view through the payload's own registrar.
Deleting the fire outright would break this case-switch re-render, which is why the gate (not
removal) is required. A plain payload (`.content(String)`) has no registrar, so its content
changes reach the `switch` only through the coarse fire; see
[`enum-case-scoping.md`](./enum-case-scoping.md).

## Why this works (the invariant it stands on)

1. **The root registrar tree is stable for the view model's lifetime.** The interactor mutates
   a working copy of the stored state; `@FeatureState` registrars are reference types, so the
   copy shares the same registrar tree as the stored value. The commit is a single plain store,
   and a content-equal wholesale replacement keeps the stored value instead (the
   `areStatesEqual` gate). So the registrar tree rooted at the stored state persists.
2. **Wholesale nested rebuilds preserve nested registrar instances when content is equal.**
   Guaranteed by the identity-preserving assignment: `state.section = rebuilt` routes through the
   `Value: FeatureState` `mutate` overload, which keeps `section` (and its registrar) when the
   content is equal and fires `\.section` when it changed.

Therefore a reader registered on the state's registrars sees every relevant change, never
observes a stale snapshot, and — with the coarse fire gated on a root `_$id` change — is no
longer invalidated by unrelated in-place mutations, while enum-root `switch` views still get the
coarse signal on a case change.

### Precision model (document this clearly)

- The interactor mutates **in place** (`state.section.title = x`): `didModify` finds the section
  identity unchanged and does **not** fire `\.section`; only `section`'s registrar fires
  `\.title`. A reader of `\.section.subtitle` is **not** invalidated. ✅ maximally fine-grained.
- The interactor **rebuilds a child wholesale** (`state.section = Section(...)`, content
  changed): the `FeatureState` `mutate` overload fires `\.section` at the parent and replaces the
  child. A reader of `\.section.subtitle` **is** invalidated even if `subtitle` didn't change,
  because `\.section` fired. Still correct and leak-free. Prefer in-place mutation in interactors
  for maximum precision.
- The interactor rebuilds a child with **equal** content: silent; the child's `_$id` and
  registrar are preserved.

The [FeatureState](./feature-state.md#observation-guarantees) guarantees table lists every case
the suite asserts.

## Source

### `Sources/Lattice/Presentation/ViewModel/ViewModel.swift`

The gate lives in the commit step. Because the working copy shares the stored state's
registrars, the nested registrars fire the precise key paths during `interact(state:action:)`;
the coarse `\.state` is reserved for root identity and case changes (the enum-switch case),
matching TCA:

```swift
private func commit(_ transition: ActionTransition<State, Action>) {
    let newState = transition.currentState
    let isReplacement = newState._$id != _state._$id
    if isReplacement, let areStatesEqual, areStatesEqual(_state, newState) {
        // Content-equal wholesale replacement: keep the current value so its registrar tree —
        // and every observer registered on it — survives. Nothing changed for the view.
        return
    }
    _state = newState
    if isReplacement {
        _$observationRegistrar.withMutation(of: self, keyPath: \.state) {}
    }
}
```

- The internal `state` getter registers `\.state`, and both `viewState` and the dynamic member
  subscript read through it, so a root fire re-renders every reader.
- In-place mutations leave the root `_$id` stable, so they fire nothing coarse and are driven
  entirely by the nested registrars.
- This mirrors TCA's `Store` pipeline, which projects `didSet` to `_$id`, applies
  `removeDuplicates()`, and only then fires `withMutation(of: self, keyPath: \.currentState)`.
- `viewModel.<member>` and every `_ViewModelBinding` getter
  ([`ViewModelBinding.swift`](../Sources/Lattice/Presentation/ViewModel/ViewModelBinding.swift))
  are fine-grained automatically, because they read through the nested tracked getters of the
  `ViewState` projection.

> **History.** The gate first shipped in a `_modify` accessor on the stored state. That accessor
> held a formal write access open across the whole action, so a synchronous observer that
> re-read the view model mid-mutation (e.g. SwiftUI body re-evaluation triggered by a tracked
> `willSet`) trapped with a Swift exclusivity error. The accessor was removed: the interactor now
> mutates a local working copy, and the commit is a single plain store followed by the gate.
> `ViewModelReentrancyTests` is the regression. The unified feature state then removed the
> projection step that ran between the interactor and the commit, and added the `areStatesEqual`
> root gate. The observable behavior described in this section is unchanged.

No macro changes and no action-loop changes were needed.

## Usage

```swift
struct DashboardView: View {
    @State var viewModel: ViewModel<DashboardFeature>

    var body: some View {
        VStack {
            HeaderView(viewModel: viewModel)
            FooterView(viewModel: viewModel)
        }
    }
}

struct HeaderView: View {
    let viewModel: ViewModel<DashboardFeature>
    var body: some View {
        // Re-renders only when header.title changes — NOT when footer or any other member changes.
        Text(viewModel.header.title)
    }
}
```

Bindings are likewise fine-grained:

```swift
TextField("Name", text: $viewModel.name.sending(\.nameChanged))  // re-renders only on `name`
```

A visible computed member is fine-grained over the members it reads, `@Domain` ones included:
reading `viewModel.updatedText` below re-renders on `updatedAt` changes even though views cannot
read `updatedAt` itself.

## Tests

`Tests/LatticeTests/PresentationTests/FineGrainedObservationTests.swift` (excerpt):

```swift
@FeatureState private struct Section: Equatable, Sendable {
    var title: String
    var subtitle: String
}

@FeatureState private struct DashState: Equatable, Sendable {
    var header = Section(title: "h", subtitle: "s")
    var count = 0
    @Domain var updatedAt = 0
    var updatedText: String { updatedAt == 0 ? "Never" : "Updated at \(updatedAt)" }
}

@MainActor
@Suite struct FineGrainedObservationTests {
    private func makeViewModel() -> ViewModel<Feature<DashAction, DashState>> {
        ViewModel(initialState: DashState(), feature: Feature(interactor: DashInteractor()))
    }

    @Test func unrelatedLeafChangeDoesNotInvalidate() {
        let vm = makeViewModel()
        let title = ObservationProbe { _ = vm.header.title }

        vm.sendViewEvent(.bumpCount)  // changes count, not header.title
        #expect(!title.didFire)
    }

    @Test func inPlaceNestedLeafMutationFiresOnlyThatLeaf() {
        let vm = makeViewModel()
        let title = ObservationProbe { _ = vm.header.title }
        let subtitle = ObservationProbe { _ = vm.header.subtitle }
        let count = ObservationProbe { _ = vm.count }
        let root = ObservationProbe { _ = vm.viewState }

        vm.sendViewEvent(.setTitle("new"))  // only title changes, in place
        #expect(title.didFire)
        #expect(!subtitle.didFire)
        #expect(!count.didFire)
        #expect(!root.didFire)
        #expect(vm.viewState.header.title == "new")
    }

    @Test func visibleComputedMemberInvalidatesWhenItsDomainDependencyChanges() {
        let vm = makeViewModel()
        let updatedText = ObservationProbe { _ = vm.updatedText }
        let count = ObservationProbe { _ = vm.count }

        vm.sendViewEvent(.touch(5))
        #expect(updatedText.didFire)
        #expect(!count.didFire)
        #expect(vm.updatedText == "Updated at 5")
    }
}
```

## Demo project

`ExampleProject/FineGrainedExamplePackage` (the `case fineGrained` entry of `ContentView.swift`'s
`Example` enum) makes the re-render boundary *visible* in a running app, not just in tests. Its
state is one flat `@FeatureState`:

```swift
@FeatureState
struct FineGrainedState: Equatable, Sendable {
    var title: String = "Hello"
    var count: Int = 0
    @Domain var phaseActive: Bool = false

    /// The phase views show, derived from the domain-only `phaseActive` flag.
    var phase: FineGrainedPhase { phaseActive ? .active("Active!") : .idle }
}
```

`FineGrainedPhase` is a plain `@CasePathable` enum (`idle`, `active(String)`). The actions
`setTitle(String)`, `bumpCount` and `togglePhase` each mutate one member in place. The root
`FineGrainedView` reads nothing observable — its buttons only send — and composes three sibling
subviews, each given the same `ViewModel` and each holding a render counter:

```swift
struct HeaderView: View {
    let viewModel: FineGrainedViewModel
    private final class Renders { var count = 0 }
    private let renders = Renders()

    var body: some View {
        renders.count += 1
        return VStack(alignment: .leading) {
            Text(viewModel.title)  // reads only title
                .font(.title2)
            Text("HeaderView renders: \(renders.count)")
                .font(.caption)
                .foregroundStyle(.secondary)
        }
    }
}
```

`FooterView` is the symmetric twin reading `viewModel.count`, and `PhaseView` switches over
`viewModel.phase`.

Expected, demonstrable behavior:

- Tapping **“Change title”** advances only `HeaderView renders:`.
- Tapping **“Bump count”** advances only `FooterView renders:`.
- Tapping **“Toggle phase”** advances only `PhaseView renders:`: reading the computed `phase`
  registers the hidden `phaseActive` it derives from.

Each counter lives in its view value, so it starts over whenever SwiftUI re-creates that view;
compare which counter advances on a tap rather than absolute counts. `FineGrainedExampleTests`
checks the same boundaries with observation probes.
